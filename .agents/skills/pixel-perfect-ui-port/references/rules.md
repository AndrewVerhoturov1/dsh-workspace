# Правила визуального переноса v1

**Reference определяет внешний вид; target сохраняет игровую логику.** Изменять внешний вид существующего интерфейса, а не заменять обработчики, состояние игры, маршрутизацию, сохранения или архитектуру. Оставлять исходные обработчики игровых действий (например, `buyUpgrade()`).

1. Работать с одним видимым компонентом и согласованным selector pair за раз. Reference и target открываются через HTTP(S), с одинаковым viewport и исходной прокруткой 0,0. Не использовать `file://` или `networkidle` в качестве критерия готовности.
2. Сначала измерить действительные `getBoundingClientRect()`, вычисленные стили и PNG; изучить `report.json` и `diff.png`. Нельзя решать «достаточно похоже» визуально. Переходить к следующему компоненту только после verifier PASS или явно зарегистрированного блокера.
3. Не выравнивать по догадкам отрицательными margins, transforms или общей шкалой. Исправлять причину: padding, box sizing, font loading, flex/grid, размеры. Известные точные assets и шрифты использовать вместо приблизительных подмен.
4. **Не разрешены** resize PNG перед проверкой, masks, автоматическое обновление reference/baseline, увеличение tolerance ради PASS, perceptual/AA exemptions, AI scoring. Допуски: geometry не больше ±0.5 CSS px; styles — точное нормализованное значение из утверждённого списка; PNG dimensions — точно; RGBA delta по каналу 0–2, после допуска `changedPixels === 0`.
5. При расхождении размеров PNG результат BLOCK, pixel counts не считаются и `diff.png` не создаётся; исправить размер элемента, а не масштабировать PNG. `maxChannelDelta` — наибольшая необработанная разница каналов, `boundingBox` — область пикселей, превышающих допуск.
6. Захват контролируемый: дождаться selector, `document.fonts.ready`, `decode()` видимых изображений, отключить animations/transitions и дождаться двух кадров. **Такой снимок не доказывает исправность настоящих взаимодействий.**
7. Захват элемента обрезает тени/overflow вне его box. Для проверки теней, overlay, раскрытых списков выбирайте соответствующий внешний контейнер как компонент; rect x/y остаётся обязательным даже при одинаковой ширине PNG.
8. До визуальных изменений зафиксировать функциональный baseline target и ошибки консоли; после PASS провести настоящие click/hover/keyboard и проверить ключевое действие игры, navigation и отсутствие новых критических ошибок. `evaluate()` не заменяет настоящее пользовательское действие.
9. В v1 автоматически измеряется **default state**. Hover, disabled, modal, selected, tooltip и прочие состояния инспектировать отдельно при помощи VUDA и явно отражать в отчёте. Универсального state runner нет.

Коды `check.mjs`: `0` — visual PASS, `1` — visual BLOCK, `2` — ошибка конфигурации, среды либо исполнения. Visual PASS не означает functional signoff.
