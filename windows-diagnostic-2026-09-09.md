# Диагностика Windows 10 — 9 сентября 2026

## Исходные условия

- Система: Windows 10 Pro 22H2, сборка `19045.6456`, 64-разрядная.
- Последняя загрузка на момент проверки: `08.09.2026 21:52:58`.
- Текущий сеанс: `DESKTOP-4L7C3RE\andre`, не повышен до администратора.
- Пользовательский профиль не является единственной причиной: проблема воспроизводится в `TeastWin10`.

## Диск и обслуживание

- `C:` — NTFS, состояние тома `Healthy/OK`, размер около 954 ГБ, свободно около 320 ГБ.
- NVMe `XPG GAMMIX S11 Pro` и два SATA-диска средствами Windows отображаются как `Healthy/OK`.
- Признаков ожидающей перезагрузки в основных ключах CBS и Windows Update не найдено.
- `DISM /Online /Cleanup-Image /CheckHealth` и `chkdsk C: /scan` не выполнены: текущий сеанс не администраторский, Windows вернула отказ в доступе.
- В журнале NTFS при загрузке есть сообщения, что тома работоспособны; ошибок Disk/Ntfs/St​​orNVMe, указывающих на явную деградацию, в доступных данных не найдено.
- Счётчики SMART через `Get-StorageReliabilityCounter` также не прочитаны: Windows отказала в доступе к CIM из обычного сеанса.

## Целостность системных файлов

- В CBS.log последняя операция SFC успешно завершилась.
- Единственное явно исправленное повреждение в последней операции: ярлык `C:\Users\Default\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\OneDrive.lnk`.
- Исполняемые файлы `StartMenuExperienceHost.exe`, `ShellExperienceHost.exe`, `SearchApp.exe`, `SystemSettings.exe` существуют и имеют действительную подпись Microsoft Windows.
- Их `AppxManifest.xml` существуют и также подписаны Microsoft Windows.

## AppX, оболочка и StateRepository

- Для основной учётной записи `andre` пакеты имеют статус `Ok` и ожидаемые расположения:
  - `Microsoft.Windows.StartMenuExperienceHost`;
  - `Microsoft.Windows.ShellExperienceHost`;
  - `Microsoft.Windows.Search`;
  - `windows.immersivecontrolpanel`;
  - `Microsoft.WindowsTerminal`.
- При этом в снимке процессов запущен `explorer.exe`, а `StartMenuExperienceHost`, `ShellExperienceHost`, `SearchApp`, `SystemSettings` отсутствуют.
- 8 сентября около `22:07` журнал AppXDeploymentServer содержит 35 ошибок события 486 `Repairing registration` для SID `S-1-5-21-239302790-3235067425-44167425-1007` — это пользователь `TeastWin10`.
- Среди затронутых пакетов есть `StartMenuExperienceHost`, `ShellExperienceHost`, `Search`, `windows.immersivecontrolpanel` и `Windows.PrintDialog`.
- В тот же период StateRepository записал 114 предупреждений события 104: SQLite-база была `database is locked`, отдельные попытки ожидали примерно 4–10 секунд.
- AppModel-Runtime в тот же период записал ошибки `0x490` при изменении состояния ряда пакетов для SID `…-1007`.
- Папки и манифесты системных компонентов присутствуют; это указывает прежде всего на проблему пользовательской регистрации/репозитория, а не на удалённые файлы Windows.
- URI `ms-settings:` зарегистрирован в `HKCR` и попытка активации создала `SystemSettings.exe`, но процесс вскоре завершился без доступного сообщения об ошибке. Значит, сама регистрация протокола присутствует, а сбой происходит при запуске компонента.
- Для Terminal пакет существует, имеет статус `Ok`, манифест содержит приложение `WindowsTerminal.exe`; ошибка «Класс не зарегистрирован» пока не выглядит как отсутствие самого пакета и требует проверки регистрации из администраторского сеанса.

## Загрузка и сторонние службы

При загрузке `08.09.2026` обнаружены ошибки служб:

- `clash_verge_service` — автоматический запуск, файл отсутствует;
- `MSSQL$TEW_SQLEXPRESS` и `SQLTELEMETRY$TEW_SQLEXPRESS` — автоматический запуск, файлы отсутствуют;
- `zapret` — автоматический запуск, файл существует, но служба завершилась с ошибкой 1067;
- драйвер `dam` не загрузился;
- в журнале также есть тайм-аут `Steam Client Service` на 120 секунд в предыдущий запуск.

В 22:00:30 были зарегистрированы драйверы `IUProcessFilter.sys` и `IURegistryFilter.sys` из IObit Uninstaller. Это совпадает по времени с недавними действиями вокруг удаления/очистки IObit и требует осторожности, но само по себе ещё не доказывает причину повреждения AppX.

## Сеть

- DHCP, NlaSvc, netprofm, Nsi, WlanSvc и RPC работают штатно.
- Активен Wi‑Fi с адресом `192.168.0.5`, шлюзом `192.168.0.1`.
- Есть несколько виртуальных адаптеров Hyper-V, VirtualBox, VPN и туннель `happ-tun`. Сетевой сброс не выполнялся.

## Предварительный вывод

Основная подтверждённая неисправность — сбой регистрации системных AppX-компонентов через StateRepository, особенно заметный при входе нового пользователя. Он согласуется с неработающими «Пуском», «Параметрами», системными панелями и ошибкой Terminal. Медленный экран «Добро пожаловать» дополнительно может усиливаться ожиданием AppX/StateRepository и старыми автоматическими службами с отсутствующими файлами.

## Что ещё требует администратора

1. Выполнить только чтение: `DISM /CheckHealth`, при необходимости `/ScanHealth`, `chkdsk C: /scan`, SMART/счётчики накопителей.
2. Проверить `Get-AppxPackage -AllUsers` и состояние регистрации для `andre` и `TeastWin10`.
3. После подтверждения пользователя выполнить точечную перерегистрацию только `StartMenuExperienceHost`, `ShellExperienceHost`, `Search` и `immersivecontrolpanel`; массовая перерегистрация всех AppX не нужна.
4. После проверки результата отдельно решить судьбу осиротевших сторонних служб; пока они не изменялись.
5. Repair install рассматривать только если точечная регистрация не восстановит оболочку.
