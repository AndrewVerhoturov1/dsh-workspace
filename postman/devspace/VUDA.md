# VUDA: внешний ChatGPT через туннель, местные агенты напрямую

## Выбор маршрута

| Исполнитель | Рабочий маршрут | Условие |
|---|---|---|
| Внешний ChatGPT, в том числе PostmanDevspace | Плагин `VUDA Local` → OpenAI Secure MCP Tunnel → местный VUDA stdio | Плагин подключён в нужном ChatGPT workspace и его инструменты предъявлены текущему чату |
| Местный агент DSH | Прямой местный VUDA MCP, подключённый к Host | Инструменты доступны конкретной роли; туннель и облачный плагин не нужны |
| Местный агент с разрешённым shell, без прямых VUDA-инструментов | Установленный MCP SDK → VUDA stdio через `vuda-runtime.mjs` | Исполнение и точечные пути разрешены; маршрут только для местного агента |

VUDA работает с местным скрытым Chromium (`VUDA_BROWSER_PROVIDER=local`), а не с
личным Chrome, Windows GUI или встроенным браузером Orca. У местного MCP и туннеля
отдельные серверные сеансы; страницы и входы между ними автоматически не переносятся.
Для внешнего туннеля `vuda-tunnel.mjs` выделяет каждому `openai/session` собственный
дочерний VUDA и браузер: страницы, входы, localStorage, консоль и screenshot-ресурсы
разных чатов не пересекаются. Внутри одного чата действия выполняются последовательно.
Без идентификатора чата возвращается `VUDA_CHAT_SESSION_REQUIRED`, общий браузер
не подставляется. Это применяется после отдельного переключения установленного launcher;
старый launcher с прямым `startVuda` по-прежнему разделяет браузер между чатами.
Scope, writer binding и штатные Bridge/bell сохраняются; смена инструмента не разрешает
обход отказа безопасности/прав. Местный MCP и SDK этот маршрутизатор не используют.

Каждый дочерний VUDA запускается прежним `start-vuda.mjs` с проверкой фактического
аппаратного WebGL; программный renderer останавливает запуск этого браузера.
При закрытии туннельного MCP завершаются только его собственные дочерние сеансы.
Сеанс чата сохраняется до закрытия туннеля; бездействие само по себе его не сбрасывает.

Метаданные приёма/завершения запросов записываются в частный
`%LOCALAPPDATA%/DSH/integrations/vuda-tunnel/requests.jsonl`: время UTC, локальный
request ID, MCP request ID, SHA-256 идентификатора чата, метод, имя инструмента и исход.
Аргументы, результаты, текст ошибок и исходный идентификатор чата не записываются.
Это позволяет установить местное получение следующего отказавшего запроса; отсутствие
записи не раскрывает конкретный внутренний этап решения OpenAI. Журнал не включать в Git.

## Единый запуск браузера

`postman/devspace/start-vuda.mjs` — общая точка запуска для `mcp-vuda` web-профиля,
SDK (`withVudaClient`) и установленного туннеля после отдельного переключения его launcher.
Она находит уже установленный VUDA **1.1.0**, ничего не скачивает и не меняет npm-кэш.
Через общий `.agents/skills/pixel-perfect-ui-port/scripts/browser-runtime.mjs`
перед импортом VUDA задаёт его экземпляру Playwright
`headless: true`, `channel: 'chromium'`, `args: ['--enable-gpu']`, сохраняя остальные
параметры вызова и существующий запасной запуск установленного Chrome при ошибке запуска.
До передачи браузера исполнителю модуль читает `SystemInfo.getInfo` через CDP:
проверяет фактический `glRenderer` и аппаратный статус WebGL/WebGL2. SwiftShader,
WARP, другой программный renderer, отсутствие renderer или аппаратного WebGL
дают `HARDWARE_GPU_UNAVAILABLE`; созданный браузер закрывается. Наличие NVIDIA
в списке устройств не заменяет эту проверку. Ошибка CDP также останавливает запуск.
Нужен полный Chromium соответствующей версии Playwright; одного Headless Shell недостаточно.
Фактический backend и нагрузку проверяй на целевой машине; аппаратный WebGL не
исключает работу JavaScript и графического драйвера на CPU.

Все три маршрута сохраняют отдельные серверные сеансы и прежнюю изоляцию страниц.
Общий launcher очищает унаследованные credentials и задаёт local provider и пустой dotenv.
Измеритель `.agents/skills/pixel-perfect-ui-port/scripts/capture.mjs` и его doctor
используют тот же модуль аппаратного запуска с собственным браузером. Viewport, DPR,
измерения, PNG-сравнение и допуски остаются прежними; графический backend теперь
обязан быть аппаратным. Анимации игры,
частота кадров и настоящие действия не подменяются и не ограничиваются.

Для установленного туннеля после завершения текущей работы установить проверенный
`vuda-tunnel.mjs` в постоянный частный каталог (не во временный worktree) и заменить
частный `start-vuda.mjs` таким содержимым, подставив точный установленный путь модуля:

```js
import { join } from 'node:path';
import { pathToFileURL } from 'node:url';
const root = process.env.DSH_HOME || join(process.env.USERPROFILE, '.dsh');
const routerPath = join(process.env.LOCALAPPDATA, 'DSH/integrations/vuda-tunnel/vuda-tunnel.mjs');
const { startVudaTunnel } = await import(pathToFileURL(routerPath).href);
await startVudaTunnel({ root });
```

Команда туннеля продолжает ссылаться на прежний частный файл. Профили, ключи и параметры
заданий планировщика не менять. Старый launcher сохранить для отката. Не переключать туннель
на файл внутри временного worktree. Местному MCP нужен перезапуск с обновлённым
web-профилем; SDK применяет общий запуск при следующем создании своего сеанса.
Подготовка исходников/PR сама по себе не обновляет действующие процессы.

Проверка после переключения: MCP-каталог обоих подключений, фактическое использование
видеокарты вместо SwiftShader на той же сцене, CPU/GPU-нагрузка, снимки при прежних
viewport/DPR и настоящие click/hover/keyboard. Финальный pixel PASS — только прежний verifier.
Если ускорение не включилось или появились визуальные/функциональные расхождения,
не объявлять оптимизацию принятой. Не ослаблять допуски и не менять baseline ради PASS.

## Внешний ChatGPT: подключённый VUDA Local

Для внешнего ChatGPT это единственный маршрут работы с VUDA.
Используй подключённые инструменты по предъявленным схемам и проверяй эффект нужных
действий чтением состояния/снимком. Предварительная проверка серверных provider/dotenv
не нужна: эти параметры задаются при запуске сервера, а не при работе чата через MCP.
Полный каталог собирай, когда задача требует инвентаризации.
При проверке реальных событий читай
`event.isTrusted`, не создавай события программно. Полную приёмку при каждой задаче
повторять не нужно. `screenshot://...` — ресурс сеанса; нужный image-блок сохрани в
разрешённую область, без вывода base64 в чат.

Отсутствие инструментов в чате и недоступность местного сервера — разные факты.
При отсутствии нужного инструмента или ошибке MCP сообщи точный блокер без перехода
на Bash, CLI, SDK или другой браузерный инструмент. Ограничение касается только VUDA:
остальные разрешённые Bash-задачи ChatGPT и способы местных агентов не меняются.
При недоступном bell результат доступным текстом остаётся `text_fallback` по действующему контракту.

## Обслуживание установленного туннеля местным агентом

Проверенная Windows-установка: официальный `tunnel-client` v0.0.16, alias `vuda-local`.
Клиент находится в
`%LOCALAPPDATA%/DSH/tools/openai-tunnel-client/v0.0.16/bin/tunnel-client.exe`,
частная конфигурация и запуск VUDA — в `%LOCALAPPDATA%/DSH/integrations/vuda-tunnel/`.
Ключи, частные профили и журналы не копируй в Git или опубликованный REQ.

Для проверки уже работающего клиента вызови `runtimes status vuda-local --json`.
Проверь `process_running`, `healthy`, `ready`; по возвращённому `health_details_url`
проверь успешный polling компонента `control-plane`. Порт бери из ответа клиента.
До первого MCP-вызова `not_observed` допустим; наличие инструмента проверяется в чате.

Если клиент остановлен и запуск разрешён задачей, открой установленный
`Connect-VudaTunnel.ps1` из частного каталога в видимом PowerShell: человек вводит полный
ключ локально в скрытом поле. Агент ключ не извлекает; на странице ключей не запрашивай
полное состояние/снимок. Достаточно прав `Tunnels: Read, Use`, без admin key. При ручном
`runtimes connect` используй существующий `--tunnel-id` и только одну область:
`--workspace-id` **либо** `--organization-id`.

Для одного tunnel id запускай один клиент. Повторный `connect` работающего alias не
заменяет ключ; согласованная замена требует штатного stop/connect своего runtime.
Ключами управляет пользователь. Сохраняй изоляцию окружения установленного launcher:
runtime API key не передаётся VUDA. Недостающие пакеты автоматически не загружай.

Автозапуска и хранения ключа в файлах нет: после остановки/перезагрузки или истечения
срока ключа может потребоваться пользователь. После запуска проверь готовность и
нужный вызов из ChatGPT. Заверши собственные тестовые ресурсы; общий клиент не
останавливай без поручения. Автозапуск и хранение секретов не добавляй без запроса.

Официальные источники: [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels),
[клиент](https://github.com/openai/tunnel-client),
[подключение ChatGPT](https://developers.openai.com/plugins/deploy/connect-chatgpt).
Границы принятого теста — [таблица возможностей](../POSTMAN_DEVSPACE_CAPABILITIES.md#vuda-local-через-secure-mcp-tunnel-20-октября-2026).

## Местные агенты: установленный VUDA через SDK или разрешённый shell

Этот вариант использует уже установленный VUDA 1.1.0 и его MCP SDK, не требует
туннеля и не добавляет MCP namespace в каталог агента. Его можно использовать местно
при разрешённом shell и отсутствии ролевого запрета. Раздел относится только к местным
агентам; внешний ChatGPT этим маршрутом не пользуется.
Пакеты не устанавливаются, настройки Host не меняются.

Для Postman сначала прочитай закреплённое задание и правила. Leader должен разрешить чтение
локатора, пустого dotenv-файла и исполнение установленного VUDA/SDK из его npm cache.
Файлы отчёта и снимки сохраняй только в назначенный writeRoot. Наличие этого примера
само по себе доступа не выдаёт.

Из корня разрешённой исходной установки:

```sh
node postman/devspace/vuda-runtime.mjs --describe
node postman/devspace/vuda-runtime.mjs --list-tools
```

Первая команда только находит entrypoints. Вторая запускает собственный stdio-сеанс,
читает все страницы `tools/list` и закрывает его. Каталог содержит реальные схемы.
Не ищи сервер только по имени команды: bin-поля пакета — `vuda` и
`visual-ui-debug-agent`, а глобальная установка npm не обязательна.

Связанные действия выполняй внутри одного `withVudaClient`, иначе следующий процесс
не получит состояние предыдущей страницы. Пример для собственной контрольной страницы
с кнопками `#clicker`, `#hoverer`, полем `#entry` и `window.testState` (адрес сервера и
путь к модулю замени на фактически разрешённые):

```sh
node --input-type=module <<'VUDA'
import { pathToFileURL } from 'node:url';
const { withVudaClient } = await import(pathToFileURL(
  'C:/Users/Andrew/.dsh/postman/devspace/vuda-runtime.mjs').href);
await withVudaClient(async client => {
  async function call(name, args) {
    const result = await client.callTool({ name, arguments: args });
    if (result.isError) throw new Error(JSON.stringify(result.content));
    return result;
  }
  await call('playwright_navigate', { url: 'http://127.0.0.1:8765/', waitUntil: 'load' });
  await call('playwright_click', { selector: '#clicker' });
  await call('playwright_hover', { selector: '#hoverer' });
  await call('playwright_fill', { selector: '#entry', value: 'vuda-check' });
  await call('playwright_press_key', { key: 'Enter', selector: '#entry' });
  console.log(JSON.stringify(await call('playwright_evaluate', { script: 'window.testState' })));
  const shot = await call('playwright_screenshot', { name: 'vuda-check', fullPage: false });
  // Сохрани image-блок снимка в выданный writeRoot; не печатай его base64 в чат.
  console.log(JSON.stringify({ screenshotReceived: shot.content.some(c => c.type === 'image') }));
});
VUDA
```

При закрытии входного канала MCP общий launcher закрывает браузеры своего серверного
процесса, включая ещё открывающийся Chromium. Это завершает временный SDK-сеанс до
принудительного завершения Node на Windows; постоянный сеанс Host или туннеля живёт
до закрытия его собственного подключения. Чужие браузеры и серверы не затрагиваются.
`SIGINT`/`SIGTERM` закрывают тот же собственный набор; новый запуск после начала
закрытия отклоняется. Браузер, открывшийся уже после отмены, сразу закрывается.

Модуль задаёт `VUDA_BROWSER_PROVIDER=local`, пустой `DOTENV_CONFIG_PATH` и передаёт
серверу только служебное окружение ОС. `withVudaClient` закрывает свой MCP-клиент
и дочерний сервер в `finally`, в том числе при ошибке действий. Свой HTTP-сервер
закрой отдельно штатным native job control.

`VUDA_RUNTIME_UNAVAILABLE` означает, что в проверенных местах не найден полный комплект;
это не доказательство отсутствия VUDA на всём ПК. `VUDA_CONNECT_FAILED` — ошибка запуска
найденного комплекта. В обоих случаях сохрани точную диагностику и не устанавливай
зависимости без решения пользователя. Этот маршрут не добавляет namespace в каталог
ChatGPT и не является доказательством штатной доставки Leader → Bridge → ChatGPT.

## Временные проектные тесты

Для отдельной браузерной проверки используй свой разрешённый Playwright и общий
`withHardwareChromium`, вместо прямого запуска исполняемого Chrome/Headless Shell
или отдельного `chromium.launch`. Это не SDK-маршрут VUDA для внешнего ChatGPT:
он по-прежнему работает с VUDA только через подключённый MCP. Штатный проектный
тест может использовать модуль, если его чтение и исполнение разрешены заданием.

```js
import { chromium } from 'playwright';
import { withHardwareChromium } from './.agents/skills/pixel-perfect-ui-port/scripts/browser-runtime.mjs';
const controller = new AbortController(); // При отмене задачи: controller.abort().
await withHardwareChromium(chromium, async browser => {
  const page = await browser.newPage();
  await page.goto('http://127.0.0.1:8765/');
  // Настоящие действия и проверки проекта.
}, { signal: controller.signal }); // AbortSignal задачи; можно не указывать.
```

Модуль не меняет экземпляр Playwright вызывающей стороны. Собственный браузер
закрывается при успехе, ошибке, AbortSignal и SIGINT/SIGTERM; отмена прерывает
ожидание даже незавершённого callback. Параллельные браузеры и работающие
предпросмотры не затрагиваются. Постоянный браузер MCP живёт до закрытия своего
подключения. Принудительное завершение процесса средствами ОС не доставляет
SIGINT/SIGTERM и не даёт JavaScript исполнить `finally`; не заменяй им штатную отмену.

При отказе аппаратной графики сохрани точную причину и останови проверку, не
переключайся молча на CPU и не запускай другой Chrome через Bash в обход.
