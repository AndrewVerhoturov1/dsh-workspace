## Что сделано

- Исправлено восстановление постоянного POSTMAN: сначала строгий `sessionPersistence.inspect()`, затем `ctx.agents.resume()`. Создание разрешается только при точном сообщении об отсутствии сессии; при других ошибках persistence запуск останавливается без создания второго владельца.
- Сохранена модельная почта только через внутренний `Agent.followup()`.
- Sender определяется из `exec.agent.id`; текстовые `from_session` не участвуют в маршрутизации.
- Добавлены проверки границ корреляции, FIFO, занятости, TTL, очистки при уничтожении отправителя, scoped-инструментов POSTMAN и отказа при ошибке persistence.
