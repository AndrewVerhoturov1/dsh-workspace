# NodesAgent_by_Andrew

Отдельный визуальный редактор команды на базе **реального Postman owner** для нового пресета `postman-leader-ptc-nodes`. Два прежних пресета Postman не изменяются. Один `TeamDefinition` хранит семантику и сохранённый снимок ролей, `TeamLayout` — расположение на Canvas, `TeamRun` — отдельные реальные DSH Session bindings. Права задаются программно; прямые назначения проверяются по Authority/Communication, запреты инструментов важнее разрешений. Родительская иерархия DSH Sessions не равна Authority.

## Отдельная установка

В составе рабочей ветки собрать клиент `node plugins/dsh-nodes-agent-by-andrew/scripts/build-client.mjs`, подключить пакет `dsh-nodes-agent-by-andrew` в **новом тестовом DSH профиле** вместе с существующим Postman Host. Применение исходников требует отдельно разрешённого развертывания Host и новой сессии с пресетом **Postman Leader PTC — Nodes (copy)**; текущий сервер 4173 не менять и не перезапускать. Не переносить новый пресет на старые сохранённые Sessions.

После установки в обычном новом пустом Chat открыть **Use Agent Team → Edit team**: редактор занимает всю область окна, Start выберет только новый пресет. В непустом чате доступна полноэкранная вкладка **NodesAgent**. Выбрать сохранённую команду и Start. Новый Run требует нового корневого Chat и создаёт новые Session для каждой ноды; Resume оставляет прежние. Появится только один native Postman worker registry для конкретного Run. `Open Chat` использует штатный `sessions.openSubagent`. Управление Run: Pause/Resume/Stop без гарантии немедленного прерывания выполняющегося модельного вызова.

Настройки провайдера, модели и усилия применяются к настоящим запросам каждой привязанной Session; промпт и роль — к её системным инструкциям. Разрешения только сужают штатные права. Skill grants ограничивают стандартный загрузчик/каталог DSH в scope конкретного агента (включая cold resume), но не скрывают файлы и не удаляют уже прочитанное из истории. Канонические инструкции ролей Postman фиксированы. Встроенные лимиты/владение ролями показаны как фиксированные ограничения, их нельзя повысить через редактор. Devspace/Luna остаётся транспортом, не редактируемой модельной нодой.

Рабочая ветка не выполняет Git commit/push/PR и не активирует установленный DSH Host.

## Проверено в рабочем дереве

- До финального capability review выполнена команда `node --test tests/native-contract.test.js tests/domain.test.js tests/runtime.test.js tests/postman-compat.test.js` из каталога плагина: 12 адресных тестов; после исправления опечатки нового compatibility-теста его 5 тестов проверены отдельно, остальные 7 тогда прошли. После review добавлен один guard regression (всего теперь 13 сценариев), исправлено сохранение явного allowlist при вычитании deny; адресная команда `node --test --test-name-pattern="tool and skill catalog|empty effective allowlist" tests/domain.test.js tests/runtime.test.js` прошла 2/2. Она подтверждает allow X + deny X → запрет X и остальных необязательных Y, сохранение fixed required native controls и прежнее наследование при пустых grants. Остальные сценарии после этой локальной правки не перезапускались. Native contract использует настоящий rc.2 AgentRegistry/Session/ToolRuntime, task-source QuickJS PTC и JSON Domain backend, но инертный адаптер модели без внешних запросов. Проверены семь Session без bootstrap-запросов, повторные cold resume с тем же ID, конфигурация реальных request/systemPrompt, назначения Sol через вложенный PTC и чтение Definition/Run/Message/Task/TaskAttempt из заново открытого JSON хранилища.
- Сборка `node scripts/build-client.mjs` и `node --check lib/client.js` прошли. В изолированном браузере проверен именно готовый `lib/client.js` с настоящими поставляемыми React 18.3.1 и SlotCore, но имитацией RPC/Session API: общий conversation store, окно 1280×720 без выхода dialog за границы, семь нод, RU/EN, редактирование имени/модели/усилия/skill grant → Save/revision, Save As, блокировка fixed grants, native Open Chat callback и выбор нового пресета до Start на пустом Chat. Ошибок/предупреждений консоли нет. На сохранённом снимке подпись Model пуста только из-за неполного fake catalog: у моделей fixture отсутствует `label`, хотя `id`/selected value корректны; настоящий Host catalog всегда передаёт `label: m.name || m.id`. Это не проверка видимой подписи с production RPC.
- Legacy Postman bridge/worker 34/34 и PTC 26/26 PASS; после финальной new-only Sol guard-правки затронутые bridge-core 13/13 и PTC 3/3 перепроверены. Новый canonical role assembly-тест 1/1 PASS. Известный старый `postman-sol-worker.test.js` содержит устаревшее ожидание защищённого текста навыка; оно не исправлялось.

Это **не** приёмка на действующем GUI 4173 и **не** live-provider PASS. Полная установка нового плагина/пресета вместе с изменённым Postman Host, реальный новый Chat и модельные запросы остаются отдельным разрешаемым этапом. Плагин сейчас использует соседний исходный `dsh-postman-harness/lib/postman-bridge-core.js`; упаковка/развёртывание должны сохранять совместное расположение этих двух пакетов.
