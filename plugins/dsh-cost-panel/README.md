# Панель расходов DSH

Отдельный плагин для DSH 0.1.1-rc.2. Панель во всех открытых чатах размещается в штатном `conversation.composer.dock` перед старой строкой статистики; старая строка не заменяется и не изменяется. Иконки и компактные подсказки взяты из согласованного `design/token-cost-panel.html` (не из PNG).

## Учёт

Штатный `llm/stream` — одна попытка вызова модели, включая неудачные/повторные попытки и auxiliary compaction/session-title, когда вызов привязан к сессии. Вызовы без sessionId не приписываются случайному чату. Целые снимки `cost-panel/attempt` добавляются в существующий append-only журнал сессии, без второго хранилища. ID одной попытки отличает её от других вызовов в том же шаге; финальные сообщения/usage chunks того же шага не добавляются повторно. История до подключения читается из существующих assistant/chunk, assistant/message и llm/retry. Повторы до подключения observer сохраняют тот же turn/step, поэтому их usage нельзя точно разделить по попыткам: такие llm/retry отмечают число вызовов и стоимость как неполные. Исторические compaction/start без записанного usage тоже отмечают неполноту: доступные сохранённые числа остаются видимыми, потерянные сведения не восстанавливаются выдуманными числами. Неполные usage chunks и финальные снимки сохраняют ранее сообщённые поля той же попытки, не складывая её повторные снимки.

Текущий агент — только собственные события выбранной сессии после durable seedLength. Команда — корень делегирования и все уникальные descendants с origin=subagent, включая сохранённых/нерезидентных детей. Обычный fork начинает собственную команду и не тянет стоимость старого предка. Открытие дочернего чата не меняет командный итог. Чтение идёт через существующие sessions/sessionPersistence, без запуска детей.

Если журнал одного сохранённого участника не читается, доступные данные остальных и выбранного агента остаются видны, а стоимость команды считается неизвестной. Ошибка чтения выбранного чата возвращается как ошибка; неподдерживаемые обязательные события не пропускаются и не переинтерпретируются.

input/cacheRead/cacheWrite/output — непересекающиеся категории DSH; нормализацию выполняет адаптер, панель не выводит запись из роста контекста. reasoning входит в output, оценивается отдельно в подсказке и не прибавляется к итогу. Постоянный порядок: вызовы, стоимость агента, команды, вход без кэша, размышления, отдельные чтение и запись кэша, исходящие. Подтверждённый 0 показан как 0; неизвестное — «—», загрузка — «…», доступная часть — число со «*», ошибка чтения — сохранённое число с «!» либо «—». Подсказки содержат точные токены, стоимость оценки по API и причины неполноты. Доля стоимости агента скрыта при неполном знаменателе/ошибке. При частичном ответе или ошибке последние известные значения удерживаются только для той же сессии; подписки, abort и возврат к сессии сохраняются. После обновления страницы всё вновь читается из журнала.

## Цены

`model-prices.json` — обычный редактируемый вручную JSON, USD/1M токенов. checkedDate и sourceUrls фиксируют проверку официальных страниц; обновляйте этот файл периодически и сверяйте условия. Официальные страницы повторно проверены 2026-10-11. Только точное совпадение модели и поставщика (штатный codex использует справочную таблицу openai): внутренние псевдонимы не угадываются. Оценка по стандартным ценам API, не сумма подписочного счёта ChatGPT/Codex.

Порог выбирается для полного input+cacheRead+cacheWrite каждого вызова, не суммы сессии; тариф действует на весь вызов. Если prompt неполон, известные компоненты сохраняют нижнюю оценку по минимальным общим ставкам двух порогов и отмечаются неполными; это не точный тариф. Для Anthropic отсутствие фактического TTL split записи кэша не означает 5m: стоимость компонента неизвестна. Нормализованный DSH TokenUsage не сохраняет TTL split; если поставщик действительно передаёт cacheWrite5mTokens/cacheWrite1hTokens и их сумма совпадает с cacheWriteTokens, используются соответствующие ставки. Выход уже содержит рассуждения.


### Граница Codex SDK 0.85.1

Публичные [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) и [prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) подтверждают вход = uncached + read + write; Anthropic [prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) возвращает уже uncached input отдельно от read/write. Это не доказательство реальной схемы приватного Codex OAuth. SDK shared parser вычитает read/write из input, но заменяет отсутствующие input/output/read/write/reasoning нулём. Адаптер подтверждает только положительные значения: необязательные SDK нули/пропуски опускаются. Обязательные числовые input/output сохраняют совместимую форму TokenUsage, но сопровождаются inputTokensKnown:false/outputTokensKnown:false; observer исключает такие placeholders из счётчиков, сохраняя неизвестность в журнале. Ранее известные положительные поля не теряются. Реальный explicit0 после этого SDK восстановить нельзя. Исторические нули/пропуски не мигрируются, доверенные нормализованные явные нули других источников остаются известными. Reasoning не добавляется ни к input, ни к output повторно.

Таблица — Standard API-эквивалент, не фактический счёт/лимит ChatGPT/Codex: [условия Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex). Профиль не передаёт в события фактический processing tier; неизвестный режим сохраняет Standard-оценку с неполнотой, явно отличный режим не получает ставки Standard. Observer сохраняет serviceTier только если он реально передан в request options; провайдерную эмиссию это не доказывает. Синтетические тесты доказывают логику DSH, а не эмиссию приватного провайдера. Изменение SDK/развёртывание требует отдельного поддерживаемого workflow; установленный SDK здесь не менялся.

## Подключение

Пакет не требует нового сборщика: `client.js` — готовая нативная factory-запись DSH ModuleLoader с React действующего shell; Host — ESM. `npm run build` проверяет синтаксис, `npm test` выполняет целевые проверки.

В действующем профиле Web подключить пакет штатно:

    dsh plugin --profile web add <absolute-path-to-plugins/dsh-cost-panel>

CLI должен добавить зависимость и bundle из cordis.patch.yml; сохраняйте остальные зависимости/config. Новый состав client-plugin активируется при перезапуске того же DSH Host и обновлении его исходного GUI URL. Не запускайте заменяющий Vite/server; shell требует DSH BOOT. Не останавливайте Host с активными заданиями: безопасное окно перезапуска согласует владелец. Без работающего dev:web watcher не обещается автоматическое HMR.

В SDK rc.2 чтение понимает `ignorable: true`, но `Session.append` теряет эту отметку. Перед включением панели штатный `profiles/web/scripts/install-production.mjs` применяет узкую совместимую правку к SDK. Для уже установленного профиля её можно применить отдельно при остановленном Host:

    node plugins/dsh-cost-panel/session-compat.mjs <absolute-path-to-dsh-package.json> <absolute-path-to-dsh-cost-panel-package.json>

Все новые `cost-panel/attempt` сохраняются с `ignorable: true`: история читается и при отключённой панели. Неизвестные обязательные события по-прежнему отклоняются. Панель отказывается запускаться, если SDK теряет отметку, чтобы не создавать снова нечитаемую историю. В старых повреждённых журналах нужно отдельно сохранить резервную копию и добавить отметку только к служебным `cost-panel/attempt`, сохранив сообщения, номера событий и данные учёта.

Для всех старых журналов при остановленном Host:

    node plugins/dsh-cost-panel/repair-sessions.mjs <absolute-sessions-root> <new-backup-directory> <absolute-dsh-package.json>

Восстановление сначала проверяет все затронутые журналы штатным читателем и сохраняет точные исходные файлы. Меняется только отсутствующая отметка `ignorable` у `cost-panel/attempt`; остальные события и их порядок сохраняются. Неизвестное обязательное событие останавливает проверку до замены журналов. Не используйте эту команду при работающем Host. Регрессионная проверка записи и повторного открытия с отключённой панелью запускается в GitHub Actions при изменениях панели или её установщика.

Живое обновление стоимости использует существующую all-session projection feed и sessions.list subscription, без таймерного опроса или второй SSE/WebSocket. Unary RPC /cost-panel/get ограничен loopback, возвращает только агрегаты, не содержимое чатов/credentials. Запросы объединяются во время чтения, чтобы поток обновлений не отменял каждый расчёт.
