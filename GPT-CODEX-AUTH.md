# Авторизация моделей GPT в DeepSeek Harness

Инструкция проверена 6 сентября 2026 года на Windows 10 и профиле `web`.

## Как устроена авторизация

Для маршрута `openai-codex` Harness использует вход через ChatGPT по OAuth. Это
не обычный ключ OpenAI API. Результат входа хранится как закрытая запись
`grant` для маршрута `llm-pi-ai/openai-codex` в локальном файле
`.credentials.yaml`.

Файл `.credentials.yaml` содержит секреты и не должен попадать в Git. Не нужно
вставлять код устройства, OAuth-токен или ссылку перенаправления в поле
`OpenAI API key`.

## Правильный вход через код устройства

1. Запусти профиль Harness `web` обычным способом.
2. Запусти штатный поток авторизации для маршрута `openai-codex` с методом
   `oauth`. Поверхность Harness должна показать уведомление с адресом страницы
   подтверждения и одноразовым кодом.
3. Открой в обычном Google Chrome страницу
   [подтверждения устройства OpenAI](https://auth.openai.com/codex/device).
4. Войди в тот аккаунт ChatGPT, подписка которого должна использоваться в
   Harness.
5. Введи показанный Harness код устройства. Код одноразовый и действует
   ограниченное время; после истечения срока нужно начать новый поток и взять
   новый код.
6. Дождись сообщения об успешном завершении входа. Процесс авторизации должен
   сам сохранить OAuth-запись в `.credentials.yaml`.
7. Перезапусти Harness. Это нужно, чтобы новый процесс загрузил обновлённые
   учётные данные и каталог моделей.

Штатный поток авторизации можно представить так:

```ts
await ctx.authorization.begin({
  key: credentialKey('llm-pi-ai', 'openai-codex'),
  method: 'oauth',
  interaction,
})
```

Здесь `interaction` показывает уведомления, открывает страницу в браузере и
принимает код устройства. Сам поток OpenAI Codex получает OAuth-данные и
записывает их через `ctx.credentials`; вручную копировать токен не нужно.

## Выбор модели

Модель по умолчанию задаётся в пользовательском `settings.yaml`:

```yaml
agent-default-model:
  provider: openai-codex
  model: gpt-6-astra
```

Для GPT-6 Astra используется точный идентификатор `gpt-6-astra`. В официальной
документации OpenAI модель также указывается с этим идентификатором и работает
через Responses API: [руководство по моделям OpenAI](https://developers.openai.com/api/docs/guides/latest-model).

Список моделей берётся из установленного каталога `@earendil-works/pi-ai`.
Если авторизация работает, но GPT-6 Astra не показывается:

1. проверь версию `pi-ai`;
2. обнови её до версии, где есть `gpt-6-astra`;
3. перезапусти Harness после обновления.

В текущей рабочей установке модель появилась после обновления `pi-ai` с
`0.82.1` до `0.85.1`.

## Что делать при ошибке `API key is invalid`

Такая ошибка для `openai-codex` обычно означает, что истёк OAuth-доступ или
не сработало его обновление. Действуй в таком порядке:

1. полностью перезапусти Harness;
2. повтори запрос;
3. если ошибка осталась, пройди вход через новый код устройства;
4. проверь, что выбран провайдер `openai-codex`, а не обычный провайдер
   `openai` с API-ключом;
5. после успешного входа снова перезапусти Harness.

Не удаляй `.credentials.yaml` без необходимости: в нём могут находиться
рабочие учётные данные других провайдеров. Не публикуй его содержимое в
журналах, сообщениях, задачах или коммитах.

## Частые ошибки

### Код введён, но Harness продолжает выдавать старую ошибку

Скорее всего, старый процесс уже загрузил истёкший токен. Заверши старый
процесс и запусти Harness заново после успешного входа.

### В окне моделей есть только поле API-ключа

Это форма для обычных ключей и не место для OAuth-кода. Для `openai-codex`
нужен поток авторизации с методом `oauth` и кодом устройства.

### В списке нет GPT-6 Astra

Провайдер авторизован, но локальный каталог моделей устарел. Обнови
`@earendil-works/pi-ai` и перезапусти Harness. Одной повторной авторизации для
обновления каталога недостаточно.

### Браузер перенаправил на страницу входа

Сначала войди в нужный аккаунт ChatGPT, затем снова открой страницу
подтверждения устройства и введи текущий код. Не используй код из предыдущей
попытки.

## Минимальная проверка после входа

После перезапуска проверь три вещи:

- запрос к `openai-codex` выполняется без ошибки ключа;
- в выборе модели есть `GPT-6 Astra`;
- выбранная модель имеет идентификатор `gpt-6-astra`.

Если первая проверка проходит, а второй нет, проблема в каталоге `pi-ai`, а не
в авторизации.
